# I-080 — the first real p0 functional prototype gate

Work package **I-080** of `docs/implementation-plan.md`, implementing the gate case
`CASE=p0.prototype_gate` (top `mosaic_core_tb`, driver `sim/unit/tb_core_prototype.cpp`).

All commands are from `/Users/flare/MosaicRV`, Verilator 5.052 (macOS arm64).

> **The card.** *Action:* freeze the p0 no-cache configuration; from an empty build
> run `make sim PROFILE=p0` and each of the four suites' applicable manifest;
> reconcile the totals and exclusions **first**, then confirm **in the trace** that
> at least once two clusters were alive simultaneously, a remote route occurred, a
> writeback collision occurred, an out-of-order completion occurred, and retirement
> stayed in order within a hart; deliver the V-039 injected-fault reset/snapshot
> replay comparison. *Pass:* every p0 instruction/CSR/trap/ordered-memory and MMIO
> check passes with zero mismatches and zero unexplained skips; the negative
> controls fail correctly; the injected build's first divergence is reproducible;
> and the dual-cluster dynamic path **actually occurs**. *Fail:* running only the
> I-008 sequential path, needing the cache enabled at p0, silently enabling
> speculative loads, disabling the remote path, or skipping a flush corner.

## 1. The configuration that was frozen

The gate freezes p0 as **cacheless, ordered memory, two real clusters, dynamic
steering on**. Every switch is driven explicitly by the driver (`sim/unit/tb_core_prototype.cpp`,
`Runner::Cycle`), not left to a default:

| switch | value | why |
|---|---|---|
| `fab_dyn_i` | 1 (dynamic run), 0 (fixed baseline) | the dual-cluster dynamic path the card is about; the fixed run is the baseline the route comparison uses |
| `cache_en_i` | 0 | the no-cache p0 choice |
| `loc_llb_en_i`, `loc_pf_en_i`, `loc_snoop_all_i` | 0 | I-060 locality structures off |
| `vec_coalesce_dis_i` | 0 | I-084 switch untouched |
| `lane_quota_req_i` | 0 | the lane quota stays at its reset share |

The no-cache claim is not a comment: the per-program check requires
`o_pmu_dcache_txn/hit/miss/refill/wb` to all be zero. A build that silently
enabled the L1D would move those counters and fail.

**I-042 (cache), I-043 (MSHR), I-047 (SoC) and I-076 (PMU) are implemented and
green** (`config/status/implementation_status.json` marks all four delivered), so
p0's cacheless configuration is a **configuration choice, not a capability hole**.
**I-036 (speculative loads) is not delivered** and p0 does not advertise it.
This package makes no RTL change: the two-cluster RTL and the p0 corpus already
exist, and the vector RTL was not touched.

The driver runs four corpus programs through both configurations, 8 runs total:

| program | input | fixed cycles | dynamic cycles | fixed c0/c1 ALU | dynamic c0/c1 ALU | MUL/DIV | dynamic router grants c0/c1/shared/LSU | WB collisions |
|---|---|---:|---:|---|---|---:|---|---:|
| `p01_addsub` | 0 | 447 933 | 448 007 | 199 / 17 614 | 8 507 / 9 306 | 0 | 27 897 / 29 329 / 0 / 0 | 4 |
| `p06_shiftlogic` | 0 | 447 927 | 447 999 | 199 / 17 618 | 8 511 / 9 306 | 0 | 27 898 / 29 331 / 0 / 0 | 5 |
| `p11_bigmuldiv` | 0 | 448 324 | 448 394 | 193 / 17 611 | 8 498 / 9 306 | 6 | 27 885 / 29 332 / 6 / 0 | 1 |
| `p12_memwalk` | 0 | 448 673 | 448 739 | 256 / 17 669 | 8 564 / 9 361 | 0 | 27 968 / 29 404 / 0 / 0 | 14 |

The fixed baseline is badly skewed (≈99 % of ALU work in one cluster); the dynamic
steering balances it. That is the "dynamic path actually occurs" at the issue
level, and it is the same finding `fabric.integrated` (I-090) measures.

## 4. The trace conditions, with their locations

```
$ python3 tools/run_unit.py --profile p0 --case p0.prototype_gate
PASS p0.prototype_gate  task=I-080
```

The driver writes the dynamic configuration's canonical event stream to
`results/unit/p0.prototype_gate/events.<program>.txt` (via `sim/common/event_tap.cpp`,
the frozen comparison format) and prints each condition's location:

```
[trace] both clusters alive (in flight): cycle 11, in flight c0=2 c1=1 (p01_addsub)
[trace] both clusters alive (IQ occupancy): cycle 447926, c0_occ=1 c1_occ=1 (p01_addsub)
[trace] remote route: program position 1 (pc 0x0000000080000004) granted at cycle 9:
        fixed cluster 1 -> dynamic cluster 0 in p01_addsub
[trace] writeback collision: cycle 1142, arbiter collisions=1 (p01_addsub)
[trace] out-of-order completion: cycle 1139, completed rob_index=55 while head
        rob_index=54 is occupied and incomplete (p01_addsub)
[trace] in-order retirement: p12_memwalk: 71242 events, seq == event index mod 256
```

| condition | observable | first occurrence | can it fail? |
|---|---|---|---|
| two clusters alive simultaneously | both clusters hold ≥1 granted, un-retired uop in the same cycle (tracked from the DUT's grant ports); the secondary observation is both issue queues non-empty at once | cycle 11 (`p01_addsub`, c0=2 c1=1); IQ-occupancy form at cycle 447 926 | yes — `MOSAIC_DISPATCH_MUTANT_SINGLE_CLUSTER` empties cluster 1 |
| a remote route occurred | a program position the dynamic steering executed in the **other cluster** than the fixed affinity executed it in (both taken from the DUT's grant ports) | position 1, pc `0x80000004`, granted at cycle 9: fixed cluster 1 → dynamic cluster 0 (`p01_addsub`) | yes — `MOSAIC_FAB_MUTANT_NO_DELTA` leaves every position on its fixed cluster |
| a writeback collision occurred | the DUT's own `o_wb_collision_ctr` advanced (two same-bank completions in one cycle, the loser delayed) | cycle 1142 (`p01_addsub`); 24 collisions across the four programs | yes — an arbiter that never delays has the counter at zero |
| an out-of-order completion occurred | a completion published for a ROB entry that is **not** the occupied, incomplete head | cycle 1139: completed `rob_index=55` while head `rob_index=54` is occupied and incomplete | yes — an in-order completion machine publishes the head first |
| retirement stayed in order within a hart | the retire port's per-hart sequence advances by exactly one per event (`seq == event index mod 2^8`), and the stream's architecture equals the host oracle's | 284 449 events across the four programs, all advancing by one; `p12_memwalk` alone 71 242 | yes — a dropped, duplicated or reordered retire event breaks the +1 chain; the oracle signature separately catches a reordered architecture |

**On "remote route".** The integrated p0 core has **no remote-link endpoint**:
`mosaic_remote_link` (I-028) is delivered as a standalone module and its evidence
is `CASE=remote.kill_with_delayed_response`, but `mosaic_core` does not instantiate
it. The card's "remote route" is therefore defined here as the route that does
exist in this machine — a macro the dynamic steering executed in the other cluster
than the fixed affinity did — and the definition is in the driver's header comment,
not implied. As **supplementary** evidence of the cross-cluster value path, the
driver also counts operand edges whose producer and consumer executed in different
clusters: 26 271 (`p01_addsub`), 26 276 (`p06_shiftlogic`), 26 266
(`p11_bigmuldiv`), 26 388 (`p12_memwalk`), first one `producer position 2
(cluster 1) → consumer position 3 (cluster 0), register x5`. That is a measured
cross-cluster value delivery, not a remote-link transaction, and the report says
which is which.

**Architectural correctness.** For every program the dynamic run's four signature
words are compared against `python3 tools/host_oracle.py --all` (the live oracle,
not a transcription), the fixed and dynamic runs are compared event-for-event over
the whole retire stream, and the machine's standing invariants (recovery counters,
ROB occupancy, load-queue cross-check, store-queue authorisation) are checked every
cycle. `tools/host_oracle.py --all` and `--check-golden-only` both exit 0, so the
corpus did not move.

## 6. Controls

Three negative controls, run by `tools/run_core_controls.py --case p0.prototype_gate`.
Each is built from a **deleted** build directory with exactly one `-D` (the define
is on `build/p0/core_controls/<define>/build_command.txt`), must produce a binary
that differs from the shipping one, and must exit 1 naming the check it breaks.

```
$ python3 tools/run_core_controls.py --case p0.prototype_gate
building the shipping case from an empty directory...
  baseline exit=0 RESULT PASS p0.prototype_gate ...
shipping binary sha256: 1f74053753668264482790be30f93774688426d12227e7b96d6dbdae893a379f
```

| `-D` mutant | injects | exit | binary sha256 | the check it breaks (first failure) |
|---|---|---:|---|---|
| `MOSAIC_DISPATCH_MUTANT_SINGLE_CLUSTER` | the affinity never alternates; every macro goes to cluster 0 | 1 | `bf6721a1186a81846b1a227b877388c417962ad73eb3d96e6361c9b23d45491a` | `two clusters were alive simultaneously (fixed baseline, p01_addsub)` |
| `MOSAIC_FAB_MUTANT_NO_DELTA` | the fabric's strategy is held low, so the "dynamic" run is the fixed machine | 1 | `20c94dbab29d03103cd78652804dd964e0df9395d7c76abc06515188a51d3064` | `a remote route occurred` (`remote_route=never`) |
| `MOSAIC_FAB_MUTANT_DYN_SWAP_SRC` | the dynamic route's operand-value wires cross, so a two-register ALU op computes a different result | 1 | `49553acfaa2321bd1876eb38db26b20d47d7f4da394285c6610b45410a93065c` | `the dynamic p0 configuration retires the oracle's architecture` (the run diverges and ends after 292 events) |

All three mutate the binary (their sha256 differs from the shipping one), each is
built from a deleted directory with its `-D` written into
`build/p0/core_controls/<define>/build_command.txt`, and each exits 1 naming the
check it breaks. The card's two named failure modes are covered directly: "a mutant
that disables the remote route" is `MOSAIC_FAB_MUTANT_NO_DELTA`, and "a mutant that
skips a flush corner / makes the dynamic route compute the wrong thing" is
`MOSAIC_FAB_MUTANT_DYN_SWAP_SRC`.

The `MOSAIC_DISPATCH_MUTANT_SINGLE_CLUSTER` control is worth one sentence: in the
**dynamic** run the steering routes around the pinned affinity, so the mutant is
only observable on the **fixed** baseline, and the gate asserts two-cluster
liveness there too. That is why the check exists on both configurations.
